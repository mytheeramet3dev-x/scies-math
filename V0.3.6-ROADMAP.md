# scies-math-th v0.2.5 -> v0.3.6

## เป้าหมายของการเปลี่ยนรุ่น

`scies-math-th v0.2.5` มี numerical toolkit ที่กว้างแล้ว ได้แก่ linear algebra, sparse matrix, tensor, statistics, probability, optimization, autodiff, ODE/PDE, signal processing, graph และ time series

เป้าหมายของ `v0.3.6` ไม่ใช่การเพิ่มจำนวนฟังก์ชันอย่างเดียว แต่คือการทำให้ crate มี:

- numerical foundation ที่เชื่อถือได้
- exact และ symbolic mathematics เบื้องต้น
- unit และ dimensional correctness
- precision/error metadata
- verification/proof integration
- API ที่เสถียรและใช้ร่วมกับ `scies-core`, `scies-bio-th`, `scies-chem-th` และ `scies-time-th` ได้

เอกสารนี้เป็น roadmap เชิงสถาปัตยกรรม ไม่ได้หมายความว่าทุก module ของ SageMath ต้องถูกย้ายมาอยู่ใน crate เดียว

## 1. สถานะปัจจุบันใน v0.2.5

### สิ่งที่มีอยู่แล้ว

- generic และ fixed-size linear algebra
- matrix decomposition, sparse matrix และ iterative utilities
- tensor และ lazy evaluation
- probability, distributions, statistics และ regression
- optimization และ multivariable optimization
- forward/reverse autodiff
- interpolation, fitting และ special functions
- ODE, PDE และ extended numerical solvers
- FFT, convolution และ digital filters
- AR/ARMA/ARIMA, smoothing, DTW และ Kalman-style utilities
- graph algorithms, geometry และ neural-network primitives
- optional `serde` และ `parallel` feature
- module documentation และ benchmark บางส่วน

### สิ่งที่ยังขาดหรือยังไม่แข็งแรงพอ

1. **Exact arithmetic**
   - rational numbers
   - arbitrary-precision integers
   - arbitrary-precision real/complex values
   - interval arithmetic และ error bounds

2. **Symbolic mathematics**
   - expression tree
   - symbols, assumptions และ substitutions
   - simplification
   - polynomial/rational expressions
   - symbolic differentiation/integration
   - equation and inequality solving

3. **Units และ dimensional analysis**
   - typed quantities
   - unit conversion
   - dimensional checking
   - compatibilityกับ physics, chemistry, biology และ time

4. **Verification และ derivation metadata**
   - derivation tree
   - assumptions ที่ใช้คำนวณ
   - result provenance
   - distinction ระหว่าง computed, estimated และ formally verified
   - bridge ไปยัง Lean 4 + Mathlib4

5. **Numerical correctness contract**
   - convergence tests
   - stability tests
   - tolerance policy กลาง
   - reproducibility policy
   - overflow, NaN และ ill-conditioned input handling

6. **API และ module consistency**
   - naming และ error model ยังควรทำให้เป็นรูปแบบเดียวกัน
   - มีทั้ง API ที่รับ `f64` โดยตรงและ API generic แต่ยังไม่มี boundary ชัดเจน
   - เอกสารยังมีความลึกไม่เท่ากันในแต่ละ module

7. **Validation corpus และ benchmark corpus**
   - ยังขาด reference cases จากตำราคณิตศาสตร์
   - ยังขาด cross-check กับ SageMath/SymPy หรือ reference implementation
   - benchmark ยังไม่ครอบคลุมทุก hot path

8. **Domain coverage ที่สำคัญ**
   - symbolic algebra
   - number theory เชิงลึก
   - abstract algebra
   - differential geometry
   - control และ estimation ที่เป็นระบบ
   - mathematical physics และ scientific units

## 2. หลักการของ v0.3.x

### แยก numerical result ออกจาก mathematical claim

```text
numeric result
  value + tolerance + method

mathematical claim
  expression + assumptions + derivation + verification status
```

การคำนวณได้ค่า `2.0` ไม่ได้แปลว่าได้พิสูจน์ theorem แล้ว ระบบต้องรายงานสถานะคนละแบบ

### ไม่ผูก core กับ SageMath หรือ Lean

SageMath, SymPy และ Lean 4 + Mathlib4 ควรเป็น optional external tools หรือ verification adapters ส่วน native core ต้อง compile และทำงานได้โดยไม่มีเครื่องมือเหล่านั้น

### ไม่เพิ่ม API ที่ไม่มี test contract

ทุก public function ใหม่ต้องมี:

- input validation
- error behavior
- unit test
- edge-case test
- numerical reference test เมื่อเป็น algorithm เชิงตัวเลข
- documentation example

## 3. Roadmap รุ่นย่อย

### v0.3.0 - Foundation Hardening

เป้าหมาย: ทำให้ฐานปัจจุบันเสถียรก่อนเพิ่ม symbolic layer

- สร้าง error taxonomy กลาง
- กำหนด tolerance และ floating-point policy
- ตรวจ NaN, infinity, overflow และ empty input ให้สม่ำเสมอ
- ทำ API naming และ result type ให้สอดคล้อง
- เพิ่ม property tests สำหรับ matrix, tensor, statistics และ transforms
- เพิ่ม deterministic seed policy สำหรับ RNG และ Monte Carlo
- แยก public API ที่เสถียรออกจาก experimental API

**เสร็จเมื่อ:** ทุก module หลักมี validation และ test contract เดียวกัน และไม่มี public function สำคัญที่ panic จาก input ปกติ

### v0.3.1 - Exact Core

เป้าหมาย: มีตัวเลข exact ที่ใช้กับ algebra และ reasoning ได้

- `Rational`
- arbitrary-precision integer abstraction
- exact complex representation เบื้องต้น
- `Interval<T>` สำหรับค่าที่มีขอบเขตความคลาดเคลื่อน
- conversion ระหว่าง exact และ floating-point พร้อม metadata
- arithmetic tests เทียบกับ known mathematical identities

**เสร็จเมื่อ:** โจทย์ rational arithmetic, polynomial coefficients และ error bounds ทำซ้ำได้โดยไม่สูญเสีย precision โดยไม่จำเป็น

### v0.3.2 - Symbolic Kernel

เป้าหมาย: สร้าง expression layer ที่ `scies-core` และ proof adapter ใช้ได้

```rust
pub enum Expr {
    Integer(i128),
    Rational(Rational),
    Symbol(SymbolId),
    Add(Vec<Expr>),
    Mul(Vec<Expr>),
    Pow(Box<Expr>, Box<Expr>),
    Function(Function, Vec<Expr>),
}
```

- expression tree
- canonical form เบื้องต้น
- substitution
- assumptions
- simplification ที่บอกเงื่อนไขได้
- symbolic derivative
- polynomial expansion และ factor helpers

**เสร็จเมื่อ:** ระบบสร้างและแปลง expression ได้ deterministic และไม่ลบ assumptions สำคัญระหว่าง simplify

### v0.3.3 - Solvers and Units

เป้าหมาย: ขยาย symbolic layer ให้แก้โจทย์และตรวจความหมายของปริมาณได้

- polynomial equation solver
- linear symbolic system
- inequality primitives
- `Dimension`
- `Quantity<T, U>`
- unit conversion และ derived units
- dimensional-analysis errors

ตัวอย่างข้อผิดพลาดที่ต้องตรวจได้:

```text
distance / duration = velocity
mass + temperature = invalid
```

**เสร็จเมื่อ:** `scies-physics-th`, `scies-chem-th` และ `scies-time-th` ใช้ quantity model ร่วมกันได้โดยไม่ต้องเขียน unit conversion ซ้ำ

### v0.3.4 - Derivation and Verification Bridge

เป้าหมาย: เก็บสายการคำนวณและส่ง proposition ไปยัง external prover ได้

- derivation tree
- assumptions และ side conditions
- provenance ของ input และ algorithm
- `VerificationStatus`
- export format สำหรับ Lean proposition
- optional Lean 4 + Mathlib4 adapter
- import ผลตรวจกลับเข้า result metadata

```rust
pub enum VerificationStatus {
    Unchecked,
    NumericallyTested,
    SymbolicallyDerived,
    FormallyVerified,
    Refuted,
}
```

**เสร็จเมื่อ:** ผลลัพธ์หนึ่งรายการสามารถบอกได้ว่าใช้สมมติฐานอะไร คำนวณด้วยวิธีใด และผ่าน verification ระดับใด

### v0.3.5 - Scientific Domain Layer

เป้าหมาย: ทำให้ math crate เป็นฐานร่วมของ crates ในซีรีส์

- common vector/matrix interfaces สำหรับ physics และ biology
- ODE/PDE result metadata และ conservation checks
- uncertainty propagation
- statistics สำหรับ measurement และ calibration
- graph/optimization interfaces สำหรับ pathway, network และ temporal models
- adapter contracts สำหรับ chemistry quantities, biology sequences และ time models
- reference datasets สำหรับ numerical methods ที่ใช้ข้าม crate

**เสร็จเมื่อ:** domain crates ใช้ primitive ร่วมกันได้ โดยไม่ต้องแปลง `f64`, matrix และ unit แบบ ad hoc ในทุกโปรเจกต์

### v0.3.6 - Release and Compatibility

เป้าหมาย: ปิดงานรุ่น 0.3 ให้เป็น release ที่ใช้งานจริงได้

- API audit และ deprecation policy
- public API documentation ครบ
- doctest และ integration test ครบ
- benchmark report ก่อน/หลัง v0.2.5
- compatibility guide สำหรับผู้ใช้เดิม
- feature matrix: default, `serde`, `parallel`, `math`, `proof`
- reproducible build และ pinned validation environment
- test fixtures จาก reference systems โดยไม่ทำให้ runtime ต้องพึ่งระบบภายนอก
- changelog และ migration notes

**เสร็จเมื่อ:** ผู้ใช้สามารถอัปเกรดจาก `0.2.5` ตาม migration guide ได้ และ core crate ทำงานได้โดยไม่ต้องติดตั้ง SageMath หรือ Lean

## 5. ความสัมพันธ์กับ SCIES

```text
scies-math-th
  numeric, exact, symbolic, units, derivations

scies-physics-th
  physical laws and models

scies-chem-th
  molecules, reactions, stoichiometry

scies-bio-th
  sequences, alignment, biological computation

scies-time-th
  timestamp, clocks, temporal models

scies-core
  concepts, beliefs, reasoning, GBS, explanations
```

`scies-core` ควรเก็บผลลัพธ์จาก math เป็น relation ที่มี provenance ไม่ใช่เก็บเพียงตัวเลขคำตอบ:

```text
equation --has_solution--> x = 2
solution --derived_by--> quadratic_formula
solution --assumes--> a != 0
solution --verification_status--> formally_verified
```

## 6. เกณฑ์วัดความสำเร็จของ v0.3.6

- ไม่มี panic จาก invalid input ใน public API หลัก
- ทุก solver สำคัญมี convergence/stability test
- ผลลัพธ์ numerical มี tolerance หรือ uncertainty เมื่อเหมาะสม
- exact arithmetic รองรับ rational workflows
- symbolic expression มี deterministic normalization
- units ตรวจ dimensional mismatch ได้
- derivation มี provenance และ assumptions
- มี proof adapter แบบ optional
- domain crates ใช้ shared primitives ได้
- documentation และ migration guide ครบ
- default build ยังไม่ต้องพึ่ง external runtime

## 7. สิ่งที่ยังไม่ควรรับปากใน v0.3.6

- ความครอบคลุมเทียบเท่า SageMath ทุกสาขา
- theorem prover ที่แทน Lean หรือ Mathlib4
- arbitrary-precision ทุก algorithm
- GPU backend ที่เสถียรทุก platform
- numerical result ที่ถูกต้องโดยไม่มี assumptions หรือ error bounds

v0.3.6 ควรเป็นจุดที่ `scies-math-th` มีแกนที่ถูกต้อง ตรวจสอบได้ และต่อยอดได้ ไม่ใช่จุดสิ้นสุดของ mathematics ทั้งหมด
